conninfpy.influence

Descriptive per-subject leave-one-out (LOO) influence for an explicitly chosen set of edges of a finished result. It refits the native model once per subject on one fewer observation and reports Δ = c'β_full − c'β_(−s), the recomputed native statistic, its df and n, the leverage of that edge’s design, the edge’s MAD and a status per subject × edge. There is no permutation, no random number generation, no p-value and no selected-edge search; the source result is never modified.

Descriptive per-subject leave-one-out influence on explicitly chosen edges.

This module answers one question about a finished inference result: which subjects drive the native contrast effect c'β and the native statistic on a small, caller-chosen set of edges? Nothing is tested again. There is no permutation run, no random number generator, no p-value, no selected-edge search and no threshold; the source result is read only.

Contract

  • Explicit edges only. edges is a finite list of unique, off-diagonal ROI index pairs, canonicalised to i < j, capped at MAX_EDGES (64). Duplicates, diagonal entries, out-of-range indices, more than 64 pairs and edges outside the producer’s estimable/tested provenance masks raise ValueError before any computation. There is no select='significant' option and no component/block aggregation. The report is also capped at MAX_RECORDS (4096) subject × edge records: the refit grows quadratically with the number of subjects, so a larger request is refused as unavailable before any refit, never run quietly.

  • Leave-one-out, not resampling. For every subject and every chosen edge the native model is refitted without that subject’s row: Δ_s = c'β_full − c'β_(−s) on the analysis scale, the statistic and its df recomputed with the same formula the source test used, and the leverage of that edge’s design recorded. Leverage is per edge, on the rows the edge actually uses: 1/n_edge of the relevant group for a pairwise equivalent design, and the hat-matrix diagonal of the edge’s coverage-row design for a GLM (X_pinv[:, s] · X[s, :], never by materialising an n × n hat matrix). A row outside an edge’s coverage has no leverage on that edge and gets None with the not_in_coverage status; no full-design leverage is reported, so two designs never share one column. For a paired design the deletion unit is the whole subject pair (the row leaves both conditions).

  • Native units. Effects and Δ are in the response units of the source model (e.g. Fisher z, or the Fisher z difference B − A for a paired result), never standardised and never rescaled.

  • Inputs are not reconstructed. A result carries coefficient maps and a design description, not the data that produced it. The caller supplies the tested inputs (the conninfpy.analyze() arguments): group1, group2, or Y plus design_matrix. A compatibility check refits the full model on those inputs and requires it to reproduce result.beta at CHECK_TOLERANCE (off-diagonal cells; the diagonal is structurally zero in a connectivity result, and available-case GLM edges are checked on their own coverage rows); a mismatch is reported as unavailable with the reason “inputs do not reproduce the tested model”. A positive Δ means the full-sample effect is larger than without that subject, i.e. the subject pulled the effect down. The check does not prove that every row is correctly aligned — row order, subject IDs and the analysis scale must be supplied correctly by the caller.

  • Paired alignment. When the source result recorded a non-identity design['paired_alignment'], either name the subjects with ids_group1/ids_group2 (the subject-ID permutation is verified against the record and applied exactly once) or declare the inputs already aligned with paired_inputs_aligned=True (nothing is reordered, and the β reproduction check catches a wrong order). For a paired design c'β is the mean B − A and is therefore invariant to the row pairing: there the beta check cannot detect a wrong order, and the observed-statistic check is the guard. IDs without a recorded alignment, or a non-identity alignment without IDs or that flag, are reported as unavailable with the reason.

  • Harmonization is not refit. ComBat and other sample-dependent transforms are fixed: the caller passes the already processed inputs, and the report notes that LOO is conditional on the fitted harmonization.

  • Unavailable, never invented. Missing input data, legacy results without coefficient maps, omnibus F results, multi-row contrasts, undeclared var_equal, statistic mismatches and missing provenance masks are reported as unavailable with a reason. A subject × edge entry whose refit is undefined (constant values, rank loss, no residual df, non-estimable contrast, no coverage) gets delta/t set to None with a status, never a made-up number.

Statuses (per subject × edge, field status)

ok, zero_mad (the edge’s MAD is 0 without its values being identical, i.e. majority ties plus at least one outlying value — the LOO Δ shows which), constant (all values identical, variance 0, t undefined), rank_loss (the design lost rank after the deletion), not_estimable (the contrast is not a combination of the rows of the reduced design), no_residual_df, not_in_coverage (the subject has no value on that edge; Δ is factually 0 and the statistic does not change) and nan_edge. zero_mad is deliberately distinct from constant: a zero MAD alone is not a constant edge. Field loo_fit_status keeps the raw status of the reduced fit, so a zero_mad row whose reduced data happen to be tied also says why its t is None.

This is a descriptive diagnostic. It says nothing about significance, about the correctness of the original inference, or about which subjects to exclude.

conninfpy.influence.subject_influence(result: Any, *, edges: Sequence[Tuple[int, int]], group1: NDArray[float64] | None = None, group2: NDArray[float64] | None = None, Y: NDArray[float64] | None = None, design_matrix: NDArray[float64] | None = None, var_equal: bool | None = None, ids_group1: Sequence[Any] | None = None, ids_group2: Sequence[Any] | None = None, paired_inputs_aligned: bool = False) → Dict[str, Any][source]

Descriptive per-subject leave-one-out influence on explicitly chosen edges.

Parameters:

  • result (InferenceResult) – A finished result with beta, design and analysis_provenance. It is only read: no p-value, mask, sample, enhancement setting or preprocessing is touched.

  • edges (sequence of (i, j)) – Explicit, unique, off-diagonal ROI index pairs (canonicalised to i < j), at most MAX_EDGES. Each must lie inside the producer’s estimable and tested provenance masks, otherwise ValueError is raised before any computation.

  • group1 (ndarray of shape (n_subjects, N, N), optional) – The tested pairwise inputs on the analysis scale (Fisher z already applied; for a paired design the two condition matrices). group1 for one-sample; group1 and group2 for two-sample and paired.

  • group2 (ndarray of shape (n_subjects, N, N), optional) – The tested pairwise inputs on the analysis scale (Fisher z already applied; for a paired design the two condition matrices). group1 for one-sample; group1 and group2 for two-sample and paired.

  • Y (ndarray of shape (n_subjects, N, N), optional) – The tested GLM response (for a paired GLM the Δz difference).

  • design_matrix (ndarray of shape (n_subjects, p), optional) – The tested GLM design matrix, including intercept, confounds and any site dummies.

  • var_equal (bool, optional) – The two-sample variance assumption as used by the source test. It is required explicitly for a two-sample result; None makes the diagnostic unavailable instead of guessing Welch.

  • ids_group1 (sequence, optional) – Subject IDs of the paired design. With a recorded non-identity alignment they are verified against the record and the recorded permutation is applied exactly once.

  • ids_group2 (sequence, optional) – Subject IDs of the paired design. With a recorded non-identity alignment they are verified against the record and the recorded permutation is applied exactly once.

  • paired_inputs_aligned (bool, default False) – Declare group2 already in group1’s row order. Nothing is reordered; a wrong order is caught by the β reproduction check.

Returns:

JSON-serialisable descriptive report: schema version, test type, units and scale, contrast, inference-unit context, the executed compatibility checks with their tolerance, per-edge full estimates, per-subject × edge Δ/t/df/n/leverage/MAD/status entries, a per-subject summary with a ranking, unavailable reasons and limitations. descriptive_only is always True.

Return type:

dict

Notes

Only the checks listed under checks are possible from a result plus the supplied inputs: design shape, full-model β reproduction, the native statistic on the selected edges and (with available-case output) per-edge coverage. Row order, subject IDs and the analysis scale are the caller’s responsibility; the reproduction check only catches a mismatch, it does not prove row-by-row identity. Multiplying the two-sample Welch degrees of freedom by a leave-one-out variance ratio is not attempted: the df are recomputed from the reduced sample with the same Welch–Satterthwaite formula.

Example

import numpy as np
from conninfpy import analyze
from conninfpy.influence import subject_influence

result = analyze(group1=condition_a, group2=condition_b,
                 test_type="paired", method="tstat").inference

report = subject_influence(
    result,
    edges=[(4, 17), (23, 61)],          # explicitly chosen ROI pairs
    group1=condition_a,                 # the tested inputs, analysis scale
    group2=condition_b,
)
report["summary"]["top_subject_by_max_abs_delta"]
report["edges"][0]["effect"], report["edges"][0]["stat"]
[row for row in report["per_subject_edge"] if row["status"] != "ok"]

Limits

  • Inputs are the caller’s responsibility. A result carries coefficient maps and a design description, not the data. Row order, subject IDs, the analysis scale (Fisher z already applied) and the GLM design matrix must be the ones that produced the result. The report refits the full model and requires it to reproduce result.beta at 1e-5/1e-8; a mismatch is unavailable with the reason “inputs do not reproduce the tested model”, not a repaired answer.

  • Paired alignment. With a recorded non-identity design['paired_alignment'], either supply ids_group1/ids_group2 (verified against the record and applied exactly once) or pass the aligned input with paired_inputs_aligned=True. A second reorder is never applied. For a paired design the mean B − A is invariant to the row pairing, so the observed-statistic check, not the beta check, catches a wrong order.

  • Only explicit edges. At most MAX_EDGES (64) unique off-diagonal pairs, each inside the producer’s estimable and tested provenance masks; anything else raises ValueError before any computation. There is no select='significant'. The report is capped at MAX_RECORDS (4096) subject × edge records: the refit grows with the number of subjects, so a larger request returns an unavailable report with the reason instead of running.

  • Leverage is per edge. It uses the rows that edge actually uses: 1/n_edge of the relevant group for a pairwise equivalent design, and the hat-matrix diagonal of the edge’s coverage-row design for a GLM (one entry at a time, never an n × n hat matrix). A row outside an edge’s coverage has no leverage there and reports None with not_in_coverage; no full-design leverage is mixed into the same column.

  • Inference unit. For NBS/cNBS/TFNBS results the diagnostic is allowed at explicit edges but the report says that these are not independent edge discoveries and that the p-value map belongs to the component or block.

  • Native units and no hypotheses. Δ and the effect stay in the response units of the model. The recomputed t values are descriptive, not tests, and are not corrected for multiplicity.

  • Statuses instead of numbers. Constant values, non-estimable contrasts, no residual df, no coverage and all-NaN edges are reported with delta/t set to None and a status; zero_mad is kept distinct from constant because a zero MAD alone can be majority ties with one outlying value. rank_loss means the reduced design rank fell below the full fit’s rank on the same edge (not rank < p: a design may already be rank deficient); such a row keeps its delta but is excluded from the per-subject max|Δ|, the ranking and the ok counts.

  • Harmonization. ComBat and other sample-dependent transforms are fixed: the diagnostic is conditional on the fitted harmonization and never refits it.
