conninfpy.atlas

Atlas metadata and reference data.

  • AtlasInfo holds per-region labels, networks, coordinates and hemispheres: the bundled Schaefer-100/200/400 (Yeo-7) and Brainnetome BNA-246 atlases, or any CSV, label image or nilearn atlas. AtlasInfo.bna_246() groups its regions by the Brainnetome Yeo-7 division (networks='yeo17' or 'lobe' for the other groupings). Changed in October 2026: the default was the lobe grouping.

  • assign_coordinates() places MNI coordinates in a reference atlas.

  • BrainnetomeReference is the BNA-246 reference used by conninfpy.interpret: hierarchy (subregion → gyrus → lobe, homologs, cytoarchitectonic descriptions, Yeo crosswalk), label images, BrainMap profiles and the optional probabilistic and tractography maps.

Data locations, the integrity manifest and caches are described in Package organization. Brainnetome data are for non-commercial use with attribution and share-alike (conninfpy/atlas_data/NOTICE_BRAINNETOME.txt); cite Fan et al. (2016) and, for the BrainMap profiles, Laird et al. (2005, 2011) (References).

Atlas metadata, Brainnetome reference data and resource access.

classmethod from_nifti(img: Any, *, lut: Any = None, networks: Any = None, exclude: Sequence[str] = (), source: str | None = None) → AtlasInfo[source]

Build an atlas from an integer label image (NIfTI path or nibabel image).

ROIs are the non-zero label values in ascending order — the order in which nilearn’s NiftiLabelsMasker extracts them.

Parameters:

  • img (str, Path or nibabel image) – 3-D image of integer labels (0 = background). Probabilistic (4-D) atlases are not label images and are rejected.

  • lut (DataFrame, dict, str or Path, optional) – Region names (and optionally networks) per label value: a DataFrame or CSV / TSV with an id column (index, id, roi_id or label), a name column and optionally a network column (nilearn’s lut works as is); a FreeSurfer-style text LUT (id name r g b a per line); or a dict {id: name}. Unnamed labels become region_<id>.

  • networks (dict, sequence or callable, optional) – Network per ROI: {id or name: network}, one value per ROI in label order, or a function of the region name. Without it the LUT’s network column is used, and without that each region is its own group (networks == labels).

  • exclude (sequence of str) – Region names to drop (e.g. white matter or ventricles in the Harvard-Oxford subcortical atlas). Their voxels are set to 0 in atlas.image, so extraction with that image skips them too.

  • source (str, optional) – Provenance string.

Notes

The atlas keeps what the label image and the LUT state, and nothing else. Label values are read in ascending order (the order nilearn’s NiftiLabelsMasker extracts them) and label_ids keeps the original values, which need not start at 1 or be consecutive. LUT columns other than the id, name and network — a structure column included — are not carried, because AtlasInfo has no such field. A label without a LUT record is named region_<id> and gets the network 'unassigned' when the LUT carries network labels at all; a network value such as 'unknown' or 'not_applicable' is kept verbatim and never replaced by a guess. No template is recorded: the image is assumed to be on the reference grid the caller annotates with.

classmethod from_nilearn(atlas: Any, *, networks: Any = 'auto', exclude: Sequence[str] = ()) → AtlasInfo[source]

Build an atlas from a nilearn fetch_atlas_* result.

Needs a deterministic atlas and nilearn >= 0.13 (its lut table). networks='auto' reads the Yeo network from Schaefer region names (7Networks_LH_Vis_1 -> Visual, matching schaefer_100_yeo7()); other atlases have no networks, so each region is its own group unless networks is given (see from_nifti()).

Example

>>> from nilearn import datasets
>>> ho = datasets.fetch_atlas_harvard_oxford("cort-maxprob-thr25-2mm", symmetric_split=True)
>>> atlas = AtlasInfo.from_nilearn(ho)
classmethod from_coordinates(coords: Any, reference: Any = None, *, names: Sequence[str] | None = None, networks: Sequence[str] | None = None, group_by: str = 'auto', max_distance: float | None = None, source: str | None = None, space: str | None = None, reference_space: str | None = None, units: str | None = None) → AtlasInfo[source]

Describe ROIs given by MNI coordinates, placed in a reference atlas.

Typical use: ROIs centred on activation peaks, with time series extracted around them (e.g. spheres). Each coordinate is assigned to the reference region that contains it, or to the nearest region within max_distance mm; farther ones are 'unassigned'. The resulting atlas groups the ROIs for network_summary and edge tables.

Parameters:

  • coords (array of shape (n_rois, 3)) – MNI coordinates (mm), in the order of the connectivity matrix.

  • reference (AtlasInfo, NIfTI path, nibabel image, nilearn atlas, or a list of them) – Atlas to place the coordinates in. With a label image the placement is voxel-exact; an AtlasInfo without an image (e.g. the bundled Schaefer tables) falls back to the nearest region centroid, with a warning. A list is tried in order — e.g. a cortical atlas, then a subcortical one — and each coordinate takes the first atlas that assigns it.

  • names (sequence of str, optional) – ROI names; default ROI_01, ROI_02, …

  • networks (sequence of str, optional) – Network per ROI when you already have one (e.g. from the study that defined the coordinates). Overrides the grouping from the reference; the region assignment is still recorded.

  • group_by ({'auto', 'network', 'region'}) – How ROIs are grouped. 'auto' uses the reference’s networks when it has them, else its regions.

  • max_distance (float, optional) – Opt-in maximum distance (mm) to a labelled voxel or, when no image exists, a centroid. The default leaves unmatched points unassigned.

  • space (str) – Declared, matching coordinate and reference templates. No registration or template conversion is performed.

  • reference_space (str) – Declared, matching coordinate and reference templates. No registration or template conversion is performed.

  • units ({'mm'}) – Coordinates are world coordinates in millimetres.

  • source (str, optional) – Provenance string.

Returns:

networks holds the group of each ROI; assignment holds the placement table (region, network, inside, distance_mm, method).

Return type:

AtlasInfo

classmethod bna_246(with_image: bool = False, networks: str = 'yeo7') → AtlasInfo[source]

Brainnetome Atlas (Fan et al. 2016) 246-region parcellation.

Names follow BN_Atlas_246_LUT.txt. MNI coordinates are voxel-mass centroids computed from the BN_Atlas_246_1mm.nii.gz parcellation (atlas.brainnetome.org).

networks selects the grouping carried in networks: the Brainnetome division of the regions ('yeo7', default, or 'yeo17'; from bna246_hierarchy.csv, i.e. the Brainnetome Center’s subregion-to-network table; subcortical regions, which the division leaves unassigned, are ‘Subcortical’), or 'lobe' (the seven-lobe grouping Frontal / Temporal / Parietal / Insular / Limbic / Occipital / Subcortical). Changed in October 2026: the default was the lobe grouping; pass networks='lobe' to keep it.

with_image=True also attaches the bundled 1 mm label image, so from_coordinates() can place coordinates voxel-exactly.

conninfpy.atlas.assign_coordinates(coords: Any, reference: Any, *, max_distance: float | None = None, space: str | None = None, reference_space: str | None = None, units: str | None = None) → Any[source]

Place MNI coordinates in a reference atlas (or a list of atlases, in order).

Returns a table with one row per coordinate: x, y, z, the assigned region, its network (the region itself when the atlas has no networks), label_id, inside (the coordinate lies in that region), distance_mm (0 inside; else to the nearest labelled voxel, or to the region centroid without an image), method ('voxel', 'nearest voxel', 'centroid' or 'unassigned') and, for a list of atlases, atlas (the position of the atlas that assigned it). With a list, exact containment is tried across all references first, followed by opt-in bounded nearest-voxel and centroid approximations. Declare identical source/reference spaces and mm units; this function does not register images or infer templates.

structural_connectivity() → NDArray[float64] | None[source]

Population structural connectivity between BNA regions, (246, 246), or None.

Derived from the Brainnetome tractography maps (BNA_SC_3D_246.zip: for each seed region, the share of reference subjects whose probabilistic tractography reaches each voxel). Entry (a, b) is the mean of seed a’s map within region b, averaged with (b, a); the diagonal is NaN. This is the population probability of a white-matter pathway, with tractography’s limits: long association fibres and lateral callosal projections are under-detected, so a low value does not show that two regions are unconnected.

conninfpy.atlas.fetch_bna_behavioral_decoding(cache_dir: str | Path | None = None, force_download: bool = False, as_dataframe: bool = False) → Tuple[Dict[str, Dict[str, float]], Dict[str, Dict[str, float]]] | Any[source]

Brainnetome Atlas (BNA-246) BrainMap behavioral decoding data.

The forward-inference Behavioral Domain (BD) and Paradigm Class (PC) association scores (thresholded at FDR < 0.05) published with the Brainnetome Atlas (atlas.brainnetome.org) are read from the local on-demand atlas cache (CONNINFPY_ATLAS_DIR or ~/.cache/conninfpy/atlases, under the Brainnetome terms in NOTICE_BRAINNETOME.txt) without network access by default. With cache_dir or force_download=True they are downloaded from the official repository instead and cached.

Data attribution & licensing

The Behavioral Domain and Paradigm Class taxonomy and coordinate data are derived from the BrainMap database (Laird et al., 2005, 2011) and computed for the Brainnetome Atlas by Fan et al. (2016). When publishing analyses that use these decodings, please cite:

  1. Fan L, Li H, Zhuo J, et al. (2016). The Human Brainnetome Atlas: A New Brain Atlas Based on Connectional Architecture. Cerebral Cortex, 26(8):3508–3526.

  2. Laird AR, Lancaster JL, Fox PT (2005). BrainMap: The social evolution of a human brain mapping database. Neuroinformatics, 3(1):65–78.

  3. Laird AR, Eickhoff SB, Fox PM, et al. (2011). The BrainMap strategy for standardization, sharing, and meta-analysis of neuroimaging data. BMC Research Notes, 4:349.
