conninfpy.analysis

The main entry point. conninfpy.analyze() runs the standard recipe — input preparation (Fisher r→z, zero diagonal), optional multi-site harmonization, GLM or two-sample / paired inference, and permutation correction — and returns an AnalyzeResult.

High-level analyze() convenience entry-point.

Wraps the most common neuroimaging recipe in one function call:

input preparation (zero diagonal, Fisher r→z once) → ComBat (optional) → GLM with Freedman-Lane permutation → InferenceResult.

Use the lower-level compute_p_val() / compute_p_val_glm() entry-points when you need fine-grained control. Use analyze() when the standard recipe fits and you want one line of code.

The pipeline is decomposed into private stages in conninfpy._analysis_stages; analyze() below only normalizes the keyword aliases, builds the shared state and calls the stages in order.

Run the standard prepare → harmonize → GLM/two-sample → infer recipe.

Parameters:

  • Y (ndarray of shape (n_subjects, N, N), optional) – Per-subject connectivity matrices for the GLM path. Pass this with interest/confounds. Leave as None (or simply omit) when using the two-sample path via group1/group2.

  • interest (ndarray or dict of ndarray, optional) –

    GLM regressor(s) of interest. Triggers the GLM pipeline.

    • Single predictor — a 1D array of shape (n_subjects,) (or (n_subjects, 1)), e.g. age or a 0/1 group dummy. analyze() returns one AnalyzeResult.

    • Several predictors — a dict {name: vector} (e.g. {'age': age, 'sex': sex}). Each predictor is tested adjusted for the intercept, confounds and the other predictors, against its own Freedman–Lane null, with permutations shared across predictors, via compute_p_val_glm_multi(). analyze() then returns a dict mapping each name to its own AnalyzeResult.

    A bare multi-column array or a Python list of regressors is rejected (it cannot carry predictor names and would silently test only the last column) — pass a dict instead. For a joint omnibus test of several predictors use a multi-row F-contrast via compute_p_val_glm() (stat_type='fstat').

  • confounds (ndarray, optional) – Nuisance regressors for the GLM pipeline.

  • group1 (ndarray, optional) – Two-sample inputs of shape (n_i, N, N). Triggers the t-test pipeline. With interest and test_type='paired' they instead form the subject-level GLM response B minus A after transforming each condition separately to Fisher z. For test_type='paired' they are the two within-subject conditions and must be row-aligned (group1[s] and group2[s] are the same subject) unless ids_group1 / ids_group2 name the subjects.

  • group2 (ndarray, optional) – Two-sample inputs of shape (n_i, N, N). Triggers the t-test pipeline. With interest and test_type='paired' they instead form the subject-level GLM response B minus A after transforming each condition separately to Fisher z. For test_type='paired' they are the two within-subject conditions and must be row-aligned (group1[s] and group2[s] are the same subject) unless ids_group1 / ids_group2 name the subjects.

  • ids_group1 (sequence of hashable scalars, optional) –

    Subject IDs for the two paired conditions, in the row order of group1 / group2. Paired paths only (test_type='paired' with group1/group2 and no Y); passing them to a two-sample, one-sample or Y-only call raises.

    The two vectors must form a strict full bijection: the same unique, non-missing IDs on both sides, matched by Python equality of the opaque values. Nothing is normalised, stringified or type-coerced, and no ID is ever guessed from the data. None, NaN, NaT, pd.NA and empty strings are rejected as IDs, as are unhashable values. The API raises ValueError for one-sided IDs (only one condition named), an ID present in only one condition (missing pair), a repeated ID within a condition, an ID vector whose length disagrees with its array’s subject axis, and for data with mismatched shapes — silently dropping a subject or pairing the wrong rows never happens.

    Index ownership. group1 (condition A) is the reference row order and the result’s order. Exactly one permutation moves every condition-B subject-axis input — group2 and confounds_group2 — into A order before the Fisher transform, the B − A difference, the condition-confound difference and any inference. Inputs that already live in A order are validated against A and never permuted: interest (including interaction predictors), subject-level confounds, sites and confounds_group1. Edge-axis objects (edge_mask, net_labels) are invariant under a subject permutation. Without IDs the positional behaviour is unchanged.

    The applied alignment is recorded in result.design ['paired_alignment'] (reference, n_subjects, the permutation_b_to_a and identity_permutation), in flags and, on the paired-interest path, in design['paired_difference']['alignment']; it survives to_bundle().

  • ids_group2 (sequence of hashable scalars, optional) –

    Subject IDs for the two paired conditions, in the row order of group1 / group2. Paired paths only (test_type='paired' with group1/group2 and no Y); passing them to a two-sample, one-sample or Y-only call raises.

    The two vectors must form a strict full bijection: the same unique, non-missing IDs on both sides, matched by Python equality of the opaque values. Nothing is normalised, stringified or type-coerced, and no ID is ever guessed from the data. None, NaN, NaT, pd.NA and empty strings are rejected as IDs, as are unhashable values. The API raises ValueError for one-sided IDs (only one condition named), an ID present in only one condition (missing pair), a repeated ID within a condition, an ID vector whose length disagrees with its array’s subject axis, and for data with mismatched shapes — silently dropping a subject or pairing the wrong rows never happens.

Inputs that already live in A order are validated against A and never permuted: interest (including interaction predictors), subject-level confounds, sites and confounds_group1. Edge-axis objects (edge_mask, net_labels) are invariant under a subject permutation. Without IDs the positional behaviour is unchanged.

    The applied alignment is recorded in result.design ['paired_alignment'] (reference, n_subjects, the permutation_b_to_a and identity_permutation), in flags and, on the paired-interest path, in design['paired_difference']['alignment']; it survives to_bundle().

  • confounds_group1 (ndarray, optional) – Condition-varying confounds for the repeated-measures GLM path, shape (n_subjects,) or (n_subjects, k), aligned to group1 / group2 respectively. Only valid with test_type='paired'; pass both or neither. When given, the paired difference group2 - group1 is tested while the per-subject confound difference is partialled out (Freedman–Lane on the differences, via compute_p_val_paired_glm()). Use these for a confound whose value differs between conditions for the same subject (e.g. condition-level motion, arousal, reaction time). With paired interest, confounds instead specifies subject-level covariates; both kinds can be supplied and only the condition-specific covariates are differenced (B minus A).

  • confounds_group2 (ndarray, optional) – Condition-varying confounds for the repeated-measures GLM path, shape (n_subjects,) or (n_subjects, k), aligned to group1 / group2 respectively. Only valid with test_type='paired'; pass both or neither. When given, the paired difference group2 - group1 is tested while the per-subject confound difference is partialled out (Freedman–Lane on the differences, via compute_p_val_paired_glm()). Use these for a confound whose value differs between conditions for the same subject (e.g. condition-level motion, arousal, reaction time). With paired interest, confounds instead specifies subject-level covariates; both kinds can be supplied and only the condition-specific covariates are differenced (B minus A).

  • interactions (sequence of pairs of names, optional) – Requires named numeric interest predictors. Center all named predictors by their sample means and add a product column per pair, named a:b. Each named effect is tested with all other columns, including the main effects, as nuisance. Encode categories explicitly. Subject-constant nuisances (and additive site effects) cancel in the difference and do not need to be supplied. With no condition-varying confounds the paired path stays on the sign-flip t-test (exact non-asymptotic null). Either way the result keeps the positive = group2 > group1 orientation.

  • test_type (str, default 'two-sample') – Test type for the t-test pipeline (also accepts 'paired' and 'one-sample'). 'paired' combined with confounds_group1 / confounds_group2 selects the repeated-measures GLM.

  • sites (sequence, optional) – Per-subject site labels. If provided, the permutation engine is auto-stratified on sites (within-block exchangeability — equivalent to PALM’s -eb option). ComBat runs when harmonize resolves to 'combat_only' or 'combat_site_dummies_glm'. In GLM mode with sites but no confounds, 'auto' resolves to 'site_dummies_glm' (site dummies in the GLM, no ComBat). In two-sample mode with sites, ComBat is skipped and a flag asks the caller to promote the analysis to GLM with a binary interest.

  • preserve (ndarray, optional) – Covariates whose effect should be preserved through ComBat. Under 'combat_only' and 'combat_site_dummies_glm' this is set automatically to confounds; passing preserve explicitly is overridden and emits a flag because the tested variable must remain outside the ComBat design. 'site_dummies_glm' does not run ComBat, so preserve is ignored.

  • harmonize (str or None, default 'auto') –

    Selects the ComBat / site-handling strategy. Three named multi-site strategies are supported, matching the paper comparison:

    • 'combat_only' — fit ComBat with preserve = confounds only, then test on the harmonized matrix without adding site dummies to the GLM. Use this to isolate what the ComBat transform itself contributes.

    • 'combat_site_dummies_glm' — primary site-aware recipe. Fit ComBat with preserve = confounds only, deliberately excluding the tested variable, then append site dummies to the downstream GLM nuisance design. Use this when the analysis needs both a harmonized matrix and residual site control during inference.

    • 'site_dummies_glm' (or None) — skip ComBat entirely and model site as fixed-effect nuisance dummies in the same GLM that tests the variable of interest. Use this when the only deliverable is the inference result, when ComBat assumptions are questionable, or as the no-ComBat site-aware sensitivity arm.

    'auto' (default) dispatches based on the call shape:

    • GLM + sites + confounds → 'combat_site_dummies_glm'.

    • GLM + sites, no confounds → 'site_dummies_glm'.

    • GLM + no sites → no harmonization.

    • Two-sample + sites → skip ComBat with a flag asking the caller to promote to GLM with binary interest for the 'combat_site_dummies_glm' recipe.

  • input ({‘r’, ‘z’} or None, default None) – Scale of Y (or group1/group2). 'r': correlations, Fisher r→z is applied once. 'z': already on the analysis scale (e.g. Fisher z), left unchanged. None detects it: a diagonal of ones means 'r', any off-diagonal value beyond ±1 means 'z'; anything else is ambiguous and raises ValueError rather than risk transforming Fisher-z data twice. The diagonal is always zeroed; the caller’s arrays are never modified.

  • fisher_z (bool, optional) – Legacy alias: True means input='r', False means input='z'. Prefer input.

  • r_to_z (bool, default True) – Whether correlations (input='r', given or detected) are Fisher transformed before inference. False analyses the correlations as they are, as the MATLAB NBS toolbox does; the result then records design['scale'] = 'correlation' instead of 'fisher_z'. No effect for input='z'.

  • var_equal (bool, default False) – Two-sample t-test path only (group1/group2 with test_type='two-sample'): False uses Welch’s t, True Student’s t with a pooled variance (the MATLAB NBS toolbox t-test). The GLM path always uses the pooled residual variance, and paired / one-sample tests have one group, so var_equal=True raises there.

  • method (str, default 'tfnbs') – Enhancement method.

  • two_tailed (bool or None, default None) – Directional family of the corrected p-values. None (the default) and True test one two-sided family: positive and negative directions are corrected against the joint max null, so one nominal alpha covers both directions. False keeps the legacy contract of two separate one-sided families, each corrected at the nominal alpha — two families at α=0.05 do not promise a combined-direction FWER of 0.05 (use α/2 per tail for that). F-stat omnibus runs have no direction and ignore this setting. The low-level compute_p_val() / compute_p_val_glm() entry-points also default to two_tailed=True; pass two_tailed=False explicitly for separate one-sided families.

  • tested_tail ({'positive', 'negative'} or None, default None) – A directional hypothesis fixed before the run: the inference uses per-tail nulls (two_tailed=False at the kernel level) and the result is restricted to that direction — the other direction is not tested (p = 1, no detections). The result records tail_policy = 'one-sided-<tested_tail>' and tail_selection = 'prespecified', which provenance and exports report honestly. Cannot be combined with two_tailed=True or with an F-stat contrast (F is non-directional). Choosing a direction only after inspecting a finished run is a post hoc selection: use one_sided() on that result, which is marked tail_selection = 'post-hoc' instead.

  • acceleration (str or None, default None) – None gives exact empirical permutation p-values. 'gpd' / 'gamma' replace the p-values that fewer than 10 permutations reach with a fitted tail and keep all others exact — with ~200 permutations, a setting for exploratory runs.

  • n_permutations (int, default 1000) – Permutations. The same defaults apply to every entry point (conninfpy.defaults).

  • e (float or sequence of float, default 0.4, 3.0) – TFNBS exponents. Pass equal-length sequences to evaluate a whole (E, H) grid in one call. Exact integration evaluates each parameter pair; cost increases with the number of pairs. When arrays are passed the returned InferenceResult carries the parameter axis (result.is_grid == True, result.e_grid, result.h_grid); use result.select(param_idx) or pass param_idx= to significant_edges / to_csv to project to a single cell. Default (0.4, 3.0).

  • h (float or sequence of float, default 0.4, 3.0) – TFNBS exponents. Pass equal-length sequences to evaluate a whole (E, H) grid in one call. Exact integration evaluates each parameter pair; cost increases with the number of pairs. When arrays are passed the returned InferenceResult carries the parameter axis (result.is_grid == True, result.e_grid, result.h_grid); use result.select(param_idx) or pass param_idx= to significant_edges / to_csv to project to a single cell. Default (0.4, 3.0).

  • n (int or None, default None) – Exact integral if None; a positive integer uses the historical right grid.

  • rng (int, numpy.random.Generator, or None) – Reproducibility handle.

  • verbose (bool, default False) – Show a progress bar during permutation.

  • use_mp (bool, default True) – Use multiprocessing for the permutation loop.

  • n_processes (int, optional) – Worker processes for the permutation loop (capped at the number of planned permutations). None uses the available logical CPUs. Each worker runs with one BLAS/OpenMP thread. The run plan records the requested value; the effective pool size is resolved inside the engine and may be smaller.

  • progress (callable or ProgressSession, optional) – Parent-side progress reporting. A callable receives (done, total) at permutation chunk boundaries for permutations that were actually folded; total is the number of permutation executions planned for the call (see conninfpy.stats._workers.ProgressSession). Nothing is sent to the workers and no numerical result changes.

  • cancel (callable, optional) – Zero-argument predicate evaluated in the parent process at chunk boundaries. When it returns true the permutation loop stops at that boundary, the pool is terminated and joined, private task files are removed and InferenceCancelled is raised — no partial p-values and no InferenceResult are returned. A threading.Event is therefore never pickled into a worker.

  • missing ({‘raise’, ‘available_case’}, default 'raise') – Missing connectivity values (NaN), e.g. a region without signal in one subject. 'raise' stops with a report of the affected subjects and regions. 'available_case' tests each edge with the subjects who have it — no subject is dropped and nothing is filled in; edges kept by fewer than min_coverage of a group’s subjects are not tested (p = NaN). Works for two-sample, paired and one-sample designs and for GLM designs (per missingness pattern), including the ComBat strategies (per-feature available-case ComBat). The coverage report is in result.inference.missing_report and summarised in flags.

  • min_coverage (float, default 0.8) – Minimum share of each group’s subjects (or of the pairs) an edge needs under missing='available_case'.

  • atlas (AtlasInfo, optional) – ROI identities and network/hemisphere metadata in input matrix order.

  • roi_ids (sequence, optional) – Explicit original ROI IDs when the input has no suitable atlas IDs.

  • groupings (dict of str to sequence, optional) – Additional named per-ROI groupings retained alongside atlas groupings.

  • units (str, optional) – Response units for the saved effect; defaults to the declared scale or 'unknown response units' for low-level calls without a scale.

  • contrast_id (str, optional) – Original contrast/predictor name for a single result. Multi-contrast results use their dictionary keys instead.

  • preprocessing (dict, optional) – Known preprocessing facts to attach to the result’s provenance (three-state: each fact carries a value and a source; None or a missing fact means unknown, never “not applied”). Typically dataset.provenance['preprocessing'] from a loader; see conninfpy.preprocessing. Nothing is inferred from the connectivity values themselves.

  • fisher_history (sequence of dicts, optional) – Structured provenance of Fisher transforms applied to the input before this call (e.g. the app’s ingestion option or design-step button). Only meaningful with already-transformed (input='z') data; the entries are preserved verbatim as the result’s upstream history — this call never re-transforms or re-counts them. input='z' without a history records the upstream transform as unknown; input='r' transforms here and records its own entry.

  • motion_qc (mapping, optional) –

    Opt-in descriptive motion / QC-FC side-car diagnostics, computed on the native input before any Fisher/ComBat step and before inference (see conninfpy.interpret.motion_qc). Off by default: with None nothing is computed and the result is unchanged.

    Recognised keys: fd (phenotype column name or a per-observation vector aligned to the analysis observations: Y for the GLM path, group1 + group2 concatenated for the two-sample path, group1 for a paired/one-sample path), fd_group1/fd_group2 (paired conditions; fd_group2 follows the original condition-B row order and is moved into condition A’s order with the same ID permutation as the data), pheno (for FD column lookup and subject-ID checks), subject_ids (exact identity check, no normalisation), input (override the resolved 'r'/'z' scale), nuisance (an aligned design matrix including an intercept; only this enables residualisation), nuisance_names, coords/atlas/space (known ROI coordinates for the distance part), roi_ids, pool (paired pooling, only with verified identity), condition_a/condition_b, fd_units, pheno_subject_column.

    The diagnostics are returned as result.motion_qc (also attached to the wrapped inference result for report/export), with an explicit status and every unavailable reason. They add one flags entry and nothing else: p-maps, statistics, masks, sampling and RNG consumption are bit-identical with and without them.

  • **method_kwargs – Forwarded to the underlying pipeline (e.g. net_labels, min_cluster_size, threshold).

Returns:

For a single predictor / two-sample / paired call, one AnalyzeResult carrying .inference (the InferenceResult) plus optional ComBat / design diagnostics and any plain-English warning flags. For a dict interest (several predictors), a dict mapping each predictor name to its own AnalyzeResult; the shared ComBat diagnostics and flags are attached to every entry.
